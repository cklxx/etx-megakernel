# G12 conditional model preparation and execution

`validation` implements the eight eligible single-mechanism integrations:
G01/G06/G07/G08/G09/G10 for Qwen B1, and G02/G05 for DeepSeek B2/B4.
Local source preparation uses `--local-validation`; it does not manufacture a
winner, enable execution, or issue a correctness/performance certificate.

For example, write a source configuration with `record`, `model`, `batch`,
and the absolute read-only original kept `reference` directory. G09 uses
`variant: "g09"`; G10 requires `g10_up` or `g10_down`. DeepSeek additionally
accepts `fleet_export`, the existing content-verified 3fb67a6 export; it never
fetches an export or reads the mutable Fleet checkout.

```sh
python -m examples.experiment_program.validation prepare \
  --config source.json --local-validation --out NEW_PREPARATION
python -m examples.experiment_program.validation build-models \
  --preparation NEW_PREPARATION/preparation.json --out NEW_NATIVE
```

The reference directory supplies the unchanged original HIP imports/adapters.
Each preparation privately emits the current kept DSL before applying G06,
G09 or G10, preserving the current narrow-router wrappers. The emitter writes
only its private manifest; historical reference files remain unchanged.

The generated source contains exactly the selected intervention, a full
unchanged control, and private host reporting. Host reporting emits the
already recorded native token ticks and wall samples after the timed decode.
Qwen original import references are compiled separately from the candidate
bundle. The builder emits exact native identities, actual original-reference
objects, deployment-compiler resources, and matched-control static residency
and spill admission. Existing local HIP runtime absence is a real host-link
exit77: it never becomes an executable, model check or fusion certificate.
Build only one selected model pair at a time; the builder checks the 2GiB
free-space floor. No complete baseline build tree is copied.

After one current guarded control has been compiled, further Qwen preparation
builds may use `build-models --reuse-control EXACT_CONTROL_DIRECTORY`.
The helper verifies every immutable native file/dependency/reference, complete
flags/kept environment/import ABI/bundle/adapters and exact private host SHA.
It regenerates the current full DSL and graph into a private proof directory;
all generated source/plan/header bytes must match exactly. Output paths always
point to the new proof directory. Only the already byte-identical DSL is read
from the old control path. No old artifact, certificate or timing is relabeled.
A mismatch retains `REUSE_REFUSED` evidence and builds a fresh control.

After a real raw micro winner, activate the prepared mechanism:

```sh
python -m examples.experiment_program.validation activate \
  --preparation NEW_PREPARATION/preparation.json --winner admission.json \
  --out activated-preparation.json
```

`admission.json` is the same raw-admission configuration consumed by
`validation.require_admission`: `record`, `decision`, `build`, plus the
record-specific pack/variant/output-prefix fields where required. Its report
and every underlying native population are reread. An `admitted: true` flag
alone is insufficient. G05 whole-model integration needs both actual up and
down roles, rather than borrowing one role's result for the other. No combined
winner is constructed or priced by summing individual results.

For the single all-record session, G12 also accepts a dormant conditional
configuration before any micro winner exists. Its `conditional_candidates`
is an ordered list of exact `{preparation, models, template, admission}`
objects. Each template is a concrete execution configuration below with no
`winner` key. Both native arms are already compiled; dispatch never builds.
The root configuration includes `source_revision`, a nonempty
`source_snapshot`, nonempty `readiness_files`, and `input_files` sealing those
artifacts, every dormant preparation/models/template, all template input
files, and every micro build identity. The existing model/source/resource/HF
input checks run in dormant admission-disabled mode on CPU preflight.
Missing HIP/native/model/input closure remains explicitly blocked.

The future run command adds `--micro-session-directory OWNED_SESSION_ROOT`.
Only earlier records marked COMPLETE by that same source revision, whose
decision lies inside that root and matches its session seal, can be considered.
The first preregistered raw-admitted mechanism with a valid native/input
closure is activated into G12's owned output. Rejected model prerequisites
are retained in the selection receipt. No arbitrary command, invented
admission, mid-session build or post-hoc fastest model selection is accepted.
The dispatcher writes `activated-preparation.json`, `activated-run.json`,
`dispatch.json`, a complete `native-session/` and the top-level decision.
`replay` automatically revalidates conditional selection, activation and
every underlying native result when given the original conditional config.

An execution configuration has these concrete fields:

* `preparation`: activated preparation JSON; `models`: the matching native
  `models.json`. Every source, current dependency, native identity and actual
  compiler allocation is verified again.
* `winner`: raw-admission configuration; `model`, `batch`, `session_id`,
  integer `seed`, one physical `device_index`, `vllm_version: "0.27.1"`, positive `timeout_seconds`
  at most900 and positive `budget_seconds`.
* `hf_model`: existing local checkpoint directory; `goldens`: exactly B
  existing vLLM prompt/gen files, each C1024 and at least32 greedy tokens.
* Qwen `model_dir`: existing packed directory containing `vl.bin`,
  `vl.manifest`, and that same `golden_c1024.txt`.
* DeepSeek `weights`, ordered `requests` directories, and `golden_manifest`.
  Each directory must have its producer-bound NPZ, hidden states, cache,
  native tokens and binding. ETX and vLLM references must have the same prompt
  and generated sequence. Actual prompt rotations and all byte hashes are
  checked, including the producer manifest.
* `systems`: unique registered labels from S0/S2/S3/S4f/S5f/S6f/S7/S8. Every
  selected lever must pass the existing actual configuration/backend/counter
  parser. The system scope is the strongest legal configuration among this
  declared tested set.
* `input_files`: absolute paths mapped to SHA256, including preparation,
  models JSON, both native build identities, the complete local HF checkpoint,
  every packed/native weight, manifest, cache and golden above. Optional
  `runtime_env` permits only PATH/HOME/PYTHONPATH/LD_LIBRARY_PATH/TMPDIR and
  cache directories; math/trace/graph/engine flag overrides are refused.

Linux staging may explicitly set `ETX_PROGRAM_RELOCATIONS` to a sealed
`etx.path-map.v1` JSON mapping absolute original prefixes to staged prefixes.
Include the mapping JSON itself in `input_files` and pass it to native Python
children through `runtime_env` when explicitly configured. Original metadata
and SHA256 values remain unchanged; the runtime records a separate
`normalized-config.json` with resolved paths and mapping hash. No original
build or input seal is rewritten during relocation.

No arbitrary `stages` or command array is accepted. Runtime commands are
generated by the checked-in implementation, with both HF offline switches.
Preflight and dry-run initialize no HIP runtime:

```sh
python -m examples.experiment_program.validation preflight --config run.json --out UNUSED
python -m examples.experiment_program.validation dry-run --config run.json --out UNUSED
```

Only a future separately authorized `run --execute` invokes a GPU. It requires
Linux, one HIP-visible MI300 device, stable physical PCI identity, readable
actual clock/power telemetry, a linked original-checking model and admissible
whole-model allocations. It retains full stdout/stderr and bounded stage
deadlines. Inputs are fully hashed before/after the session and checked for
size/mtime/inode changes before each call. No weights are copied.

The registered schedule runs Qwen97/97 original import checks at positions0
and1040, DSL and graph gates, separate legal-system selection, five seeded
interleaved model pairs, five candidate same-kernel graph pairs (Qwen only),
and five independent candidate/selected-system pairs. Every invocation passes
its correctness gate before the next begins. DeepSeek has no graph phase:
`UNAVAILABLE_LDS_LIFETIME` remains the explicit fusion result.

The transcript binds exact ordinal/order/argv, one session and physical GPU,
current inputs/build, return codes, clock/power readings and every raw log.
System correctness requires precisely the warmup/full/short population and
five full/short samples for every request; applied proof files themselves are
sealed. Final system pairs cannot reuse the model-pair candidate observations.
Incomplete attempts have no decision and require a new output directory.

When a Qwen fold implementation decision is explicitly active, set
`fold_decision_active: true` and optional `fold_trace_positions: [0,1040]`
(default `[1040]`). Only this registered phase sets ETX_TRACE/ETX_TRACE_RAW and
the private host's ETX_PROGRAM_TRACE_POS guard. It runs after all complete
uninstrumented pairs and existing graph/import gates. The final repeat exports
the exact selected step after completion and after the wall bracket, disables
the raw filename to prevent the final1054 step overwriting it, and completes
all32 greedy checks. The implementation reserves raw/plan/proof storage plus
the protected2GiB free-space floor. Trace logs, every task row, emitted plan,
native module/source/flags, physical GPU, actual input seal and fresh checker
identity are retained under `trace/` with sealed proof JSONs.

G11 seals a captured folded-input pack with
`row_ops seal-capture --directory CAPTURE --plan EXACT_PLAN --trace-proof
G12_TRACE_PROOF --capture-build EXACT_NATIVE_CAPTURE_BUILD`. The separate
capture host may differ, but its device module, source, full flags, imports,
plan, selected position and model weight bytes must match the G12 trace.
G11 execution refuses a missing/mismatched trace or inactive fold session.
Ordinary runtime body-done stamps precede event releases/arrives; their exact
publication time is unobserved. The proof therefore establishes the current
event/queue context and never subtracts clocks across the separate sparse
replay or supplies an exact publication-to-consumer/model/removable-work
price. Matched allocations, exact intermediates/outputs, all-wave coverage
and perturbation at most0.5us still gate sparse exposure qualification.
The corresponding status is `QUALIFIED_CONSUMER_EXPOSURE`; the registered
full-chain result remains `UNAVAILABLE_PUBLICATION_TIMESTAMP`. Preparing a
qualified sparse publication-retirement diagnostic is a remaining software
diagnostic blocker, separate from missing HIP runtime or unmeasured GPU
outcomes. The ordinary body-done trace does not supply that timestamp.

```sh
python -m examples.experiment_program.validation run --execute --config run.json --out NEW_SESSION
python -m examples.experiment_program.validation replay --config NEW_SESSION/session-config.json --out NEW_SESSION
```

Revalidation also accepts the exact original registered run configuration.
`replay(..., write=False)` performs independent read-only raw revalidation.
No locally generated or historical evidence claims fresh device correctness,
system performance, or independent review.

Guard-only reuse of an already compiled complete G01 pair requires a separate
attestation: both complete current native sources/plans/headers are regenerated
and compared byte for byte, and both native identities, original reference
objects, flags, host bytes and dependencies remain unchanged. Runtime preflight
requires the attestation, original metadata and every proof file in its input
seal. It transfers no GPU check or timing, and retains missing-runtime exit77.
A changed mathematical overlay or failed target cannot use this attestation.
