# Decode latency, 2026-10-07

## Scope and decision

This report extends [the byte report](BANDWIDTH-2026-10-07.md).
The source is round11, Qwen3-30B-A3B, batch one, on one MI300X VF.
The device has eight XCDs and 304 workers.
The trace covers 1,055 KV positions and 60,362 tasks.
Its device span is 5,081.49 us.
All times below describe this single device trace unless a paragraph states another source.

The three worst requested latency phases are router, topk, and reduce.
Their phase intervals total 1,258.29 us.
The overall excess leaders remain qkv, moe_up, and moe_down.
This report does not propose new tile code for those phases.

The archive supports two cheap choices: reuse vector norm and reuse the NT/prune build.
It supports no positive, safe reduce lever under the no-GPU constraint.
The predictions below are conditional estimates, not measured gains for new code.

## Byte derivation

The plan exports task grids and kernel symbols.
It does not export activation tensor shapes or argument values.
The config supplies E=128, K=8, NH=32, NKV=4, HD=128, and V=151936.
The byte path selects audited host layouts by kernel symbol.
It refuses unsupported symbols or a grid that cannot cover the context.
It counts logical payload bytes, not physical HBM transactions.

`topk` uses `etx_tile_rep_dsl_topk`.
Each replica reads E bf16 logits.
Each replica writes K float weights, K int IDs, and K int expert indices.
Thus each task has `2*E + 12*K = 352` bytes.
Eight replicas across 48 layers give `384*352 = 135168` bytes.
The count includes replica reads because each replica executes them.
It excludes argument-block reads and cache-line amplification.
See [topk.py](../etx/ops/topk.py) and [host.hip](../examples/vllm_llm/host.hip).

`reduce` uses `etx_tile_attn_reduce` with eight query heads per KV head.
The plan has four reduce tasks and twenty attention tasks per layer.
The attention grid therefore allocates five partitions per KV head.
The imported kernel fixes each partition at 256 tokens.
The context requires `ceil(1055/256) = 5` partitions.
Each query head reads five HD-element bf16 partial vectors.
It also reads five float sums and five float maxima.
It writes one HD-element bf16 output vector.
Thus each layer has `NH*(P*(2*HD+8)+2*HD) = 50432` bytes.
Each task has 12608 bytes.
All 48 layers have 2420736 bytes.
This count excludes repeated clamped loads, sequence scalars, argument reads, and LDS traffic.
It counts the one-partition path with the same logical payload convention.
See section seven of [the kernel audit](../examples/vllm_llm/ops/hip.md).
The archived source is `results_2026-09-27/extra/b_sc1/imp/attention.hip`, lines 1418 through 1620.

`argmax` uses `vl_argmax`.
It reads V bf16 logits and writes one int token plus one uint64 timestamp.
It can also write the next input token.
The plan lacks the runtime `write_next` flag.
The CLI therefore requires `--argmax-write-next 0` or `1` for this layout.
Round11 completes greedy decode, so the report uses one.
Its count is `2*V + 4 + 8 + 4 = 303888` bytes.
A teacher-forced trace must use zero instead.
See [vl_tiles.hip](../examples/vllm_llm/vl_tiles.hip) and the host's `write_next` assignment.

The original ledger excludes activation traffic in its ten known phases.
This report preserves that scope to reproduce all original numbers.
The extra rules close three absent phase budgets; they do not complete a hardware traffic model.

## Trace method

`timeline.latency_phases` reuses `per_type`, `domain_skew`, `critical_path`, and `critical_by_type`.
It does not use a second trace analyzer.
Body time spans ready to done.
The body includes the all-wave store drain and final barrier.
These stamps cannot split computation, memory stalls, and internal synchronization.
Wait time spans taken to ready.
Wait time includes useful predecessor work, so it is not exposed synchronization overhead.

The parallel-task mean divides total task-body time by the sum of each grid's body span.
The active-XCD mean uses the exact union of body intervals on each XCD.
Its denominator uses the same grid spans.
These are task-level activity measures, not hardware wave occupancy counters.
The task capacity is 304; the XCD capacity is eight.

A dependency gap starts at the latest required producer's body end.
It ends at the consumer's ready stamp.
It includes producer event publication and consumer acquire work.
It can also include dispatch delay.
The p95 uses the nearest-rank rule across tasks.
The trace cannot separate those gap components.

The critical path has 4,204.52 us of bodies and 876.97 us of dependency gaps.
It has zero queue-gap time.
Their sum is 5,081.49 us.
These facts exclude worker-queue gaps as the dominant cost of this trace.
They do not exclude runtime work inside a body or dependency gap.

### Router

Diagnosis: memory latency at low useful occupancy, with a large work tail.
This is an inference about the body, not a memory-counter measurement.
The plan assigns 128 useful rows to the first 128 of 256 tasks.
Those tasks occupy XCDs zero through three.
The other 128 tasks exit without a row.
Across all layers, 6,144 useful tasks average 6.698 us.
The 6,144 empty tasks average 0.506 us.
The mean across both groups hides that difference.
The critical body totals 351.60 us, against 118.95 us of incoming dependency gaps.
The 339.17 us finish skew records uneven work, not a 339.17 us synchronization opportunity.
The 63.95 us start spread is much smaller than the useful body budget.

### Prep

Diagnosis: memory request latency at low occupancy.
Only 3.68 tasks execute concurrently on average.
The critical body totals 287.28 us, against 77.60 us of incoming gaps.
The phase's 13.81 us outgoing gap cannot explain its 319.15 us interval.
The trace supports a body bottleneck, but cannot prove an instruction-level dependency chain.
Round22's scalar-load hoist left the layer-11 body at 5.70/5.68 us.
That archive rejects the old claim that source-order scalar dependencies dominate prep.
It instead identifies many small coherent requests.

### Top-k

Diagnosis: memory publication latency at low task occupancy.
All eight XCDs participate, but only 7.59 tasks execute concurrently on average.
The critical body totals 393.96 us, against 72.99 us of incoming gaps.
The start spread totals only 16.95 us.
The outgoing gap totals only 9.91 us.
Thus a delayed launch or a phase handoff cannot explain most of the interval.
Round13's invalid-output ablation removed all stores and cut 223 us per token.
That ablation diagnoses publication cost; it is not a correctness-qualified optimization.
The valid unused-output variant gained only four us, within run spread.

### Reduce

Diagnosis: serial dependencies inside the imported body at low occupancy.
The trace proves the low activity and body cost; the kernel audit supplies the internal-chain inference.
Only 3.45 tasks execute concurrently on average.
The critical body totals 268.52 us, against 52.20 us of incoming gaps.
The outgoing all-head join adds 87.23 us to the phase interval.
That is 22% of the 397.35 us interval, not its dominant component.
The start spread totals 42.23 us.
The audited kernel must read partial statistics before its final output reduction.
Round22 rules out an unsafe acquire reduction and finds no latency benefit from uncached partials.

### Attention

Diagnosis: fixed imported-body latency at low occupancy.
Only 17.48 tasks execute concurrently across 3.60 active XCDs on average.
The critical body totals 310.84 us, against 49.92 us of incoming gaps.
The outgoing gap totals only 8.68 us.
Layer 11 has body durations from 5.72 to 6.68 us across twenty tasks.
The 1.17 ratio rejects the old partition-imbalance claim.
Round11's prompt/decode comparison identifies about 5.2 us of fixed partition cost.
The trace does not identify HBM latency as the cause.
The KV payload can reside in MALL.

### Output projection

Diagnosis: serial phase dependencies dominate the apparent excess gap budget.
The useful body still reads weights; low occupancy is not its main trace signature.
The phase averages 233.02 parallel tasks across 7.58 XCDs.
The critical body totals 269.44 us, against 105.26 us of incoming gaps.
The start spread totals 22.08 us, while the outgoing gap totals 95.36 us.
Thus a launch tail cannot explain most of its apparent excess.
The historical per-shape floor is 5.30 us, near this trace's 5.451 us mean body.
That floor is an estimate from the hardware probe, not the global 4.3 TB/s floor.
The trace does not justify a new output-projection tile.

## Ranked cheap levers

Rank refers to the requested latency phases, not the overall weight-phase excess list.
Each choice below uses existing code, archived traces, or a static memory contract.
None needs a new GPU experiment for this decision.
The acceptance rule requires a positive archive-backed estimate and an existing correctness gate.
Reject a candidate if its gain is nonpositive, unsafe, or within measured spread.

1. **Router: reuse the existing vector norm path. Prediction: 42.29 us of phase time.**
   Round23's control/vector traces give router intervals of 438.21/395.92 us across 48 layers.
   Their task-body means are 3.564/3.103 us.
   The critical body falls 68.44 us, but its incoming gaps grow 19.05 us.
   The phase prediction uses the interval difference, not the isolated body difference.
   The archive reports three correct pairs with a 105 us mean whole-step gain.
   This is a transfer prediction for round11, not a new measurement or an isolated router A/B.
   `ETX_VL_VECNORM` already supplies this path; no tile redesign is proposed.

2. **Top-k: reuse the existing NT/prune build. Prediction: 24.14 us of phase time.**
   Round11/final traces give top-k intervals of 422.00/397.86 us.
   Their task-body means are 8.149/7.662 us.
   Their critical bodies differ by 23.32 us.
   The final trace reports 32/32 tokens; the archived whole-step gain from both changes is 121 us.
   This prediction transfers the observed phase difference, not proof of a top-k-only causal effect.
   Keep all eight replicas and the current coherent output contract.
   Round13's store-group variant lost eight us; its unused-output variant gained four us within spread.

3. **Reduce: retain the current imported path. Prediction: zero us from the cheapest candidate.**
   The candidate is uncached partials instead of the current acquire/load path.
   Round22 gives about 690 ns for either dependent-load route.
   The predicted per-hop difference is `690-690 = 0` ns.
   The trace already places four reduce tasks on the producer XCDs.
   An acquire limited to `sc0` violates the recorded repeated-read memory contract.
   Reject both changes without a GPU run.
   No supported positive saving exists for this phase under the stated constraints.

Do not add the first two predictions.
They use different controls and can interact.
Round23's vector trace increases top-k phase time by 15.91 us against its own control.
The predictions rank cheap archive-backed choices; they are not a combined speedup promise.
The 433.0, 422.0, and 396.8 us excess values do not establish recoverable time.
