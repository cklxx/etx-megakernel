# ETX English style — STE100 target

## Scope and authority

This project targets 80% adherence to the rules below. This target is not a claim of certified ASD-STE100 compliance.
The user requires these rules for English in `README.md` and `docs/*.md`.
Preserve technical meaning before style. Preserve uncertainty, historical context, and all conditions of a measurement.

The official [STEMG site](https://www.asd-ste100.org/) identifies Issue 9, dated 2025-01-15, as the current standard.
The [Issue 9 text](https://www.asd-ste100.org/assets/files/ASD-STE100_ISSUE9.pdf) supports simple verb forms, active voice, and limits on sentence length.
It restricts verb forms with `-ing`, rather than every word with that suffix.
It permits technical nouns and modifiers with that form. It permits parentheses for specified purposes.
The ETX user requires stricter treatment of parenthetical prose. The official rules prohibit semicolons.

The [official FAQ](https://www.asd-ste100.org/STE_faq.html) explains the distinction between verb forms and technical terms.
For Issue 9, passive descriptions require an unknown agent. Do not invent an agent to force active voice.
The [download page](https://asd-ste100.org/STE_downloads.html) provides the official-copy request process.

## Rules and counterexamples

| Rule | Counterexample | Preferred expression |
|---|---|---|
| Give each sentence one main idea. | The run passes and the next model needs a different router. | The run passes. The next model needs a different router. |
| Limit each instruction to 20 words. | Run the complete benchmark on the selected GPU after all local tests pass and then copy every result to the archive. | After all local tests pass, run the complete benchmark on the selected GPU. Copy every result to the archive. |
| Limit each description to 25 words. | The compiler emits a single persistent kernel for the model and the host then supplies argument blocks for each step while the event protocol orders all tasks. | The compiler emits a single persistent kernel for the model. The host supplies argument blocks for each step. The event protocol orders all tasks. |
| Use active voice when the actor is known. | The plan is generated by the compiler. | The compiler generates the plan. |
| Use simple present, past, or future tense. | The test has demonstrated a race. | The test demonstrated a race. |
| Do not use an `-ing` verb form. | The worker waits by polling the event. | The worker polls the event until it can proceed. |
| Limit noun clusters to 3 words. | The GPU kernel launch latency budget is small. | The budget for kernel launch latency on the GPU is small. |
| Keep one topic in each paragraph. | A paragraph about event order also describes rental prices. | Put event order and rental prices in separate paragraphs. |
| Limit each paragraph to 6 sentences. | One paragraph contains seven separate test instructions. | Use a numbered list with one test instruction per item. |
| Do not join clauses with semicolons. | The build passes; the run fails. | The build passes. The run fails. |
| Do not hide prose in parentheses. | The result is correct (only at batch 1). | The result is correct only at batch 1. |
| Use one term for each technical meaning. | A paragraph calls the same ETX event a signal, gate, and barrier. | Use event for the ETX dependency object. Name a barrier only when the operation is a barrier. |
| Keep necessary words and conditions. | Fusion wins. | Fusion wins for these tiles at batch 1 on this GPU. |
| Put a prerequisite before its instruction. | Start the run if the correctness gate passes. | If the correctness gate passes, start the run. |
| Preserve protected content. | Rewrite a command option to match prose style. | Keep the command exactly as supplied. |
| Resolve numeric contradictions from raw evidence. | Replace 1.2% with a guessed percentage. | Identify the paired logs and timer basis. Calculate the percentage from those values. |

## Technical terms

| Term | Meaning in this repository |
|---|---|
| kernel | One GPU entry point or an explicitly identified imported kernel body. |
| tile | The task body that ETX executes. Do not use it as a synonym for the full kernel. |
| task | One instance of a task body with its coordinates and arguments. |
| workgroup | The hardware group of threads. Do not replace it with worker. |
| worker | The ETX executor that processes its task queue. |
| event | An ETX dependency object with a count and scope. |
| barrier | An operation that prevents progress until all required participants arrive. |
| device span | The interval between the specified GPU timestamps. |
| wall time | The interval from the host clock, with the stated host work included. |
| fusion benefit | The reduction relative to the same tiles without fusion, under equal conditions. |
| system speedup | Baseline time divided by ETX time. This ratio does not isolate fusion. |
| gate | A correctness or decision test with an explicit pass condition. |

Keep established technical nouns such as routing, scheduling, tiling, lowering, and embedding when a substitute changes the meaning.
Keep API names, model names, file paths, formulas, identifiers, commands, quotations of machine output, and code blocks unchanged.
Use `synchronization` in new prose. Retain identifiers and literal source titles with other spellings.

## Review and estimate

Review English prose in each file, including prose in table cells. Do not translate Chinese prose.
Exclude code, commands, formulas, identifiers, source quotations, and purely symbolic table cells from the style score.
Record exclusions and uncertain sentences in `docs/DOC-AUDIT-2026-10-03.md`.

Estimate adherence from sentence length, clause structure, voice, verb forms, punctuation, noun clusters, paragraph structure, and terminology.
A mechanical screen can measure some features. It cannot certify approved vocabulary, technical meaning, or all grammatical roles.
Report the percentage as an estimate with the method and limitations. Do not count an unverified rule as a pass.

Keep dated hypotheses as hypotheses. Do not replace them with later findings during a style edit.
For each numeric correction, record the old value, new value, source logs, timer basis, and calculation.
If the source evidence is insufficient, retain the claim and identify the unresolved conflict.
