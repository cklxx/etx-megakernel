Plan and host reject non-folded/non-RMS H=2048, E=128, NB=1 or fewer than

## C2: reject the accumulator reinterpretation

`dsl_gemv_rows_nb<EPL,U,NB>` documents `NB` as independent request columns,
not fragments of one output. The kept build has DSL_NB=1; every MoE call also
instantiates NB=1. The b loop is unrolled **once**, so eliminating NB-1 wave
reductions saves `(1-1) * reduction_cost = 0 us/layer [E] <0.625`.
The many ISA copies are row-transition/tail/shape sites. `cur` selects the
output row; summing accumulators across those sites mixes output rows or
changes fp32 summation order. Accumulate-then-reduce already happens across
segments of the same row. No legal once-only reduction across rows exists.
No candidate built. All six class/resource rows equal baseline (delta 0);
IR/source unchanged for this item. No correctness gate was weakened.

## C3: close priced address arithmetic

Prep's BS could be specialized to 16: the imported attention operator fixes
BS=16 (`model.py` derives BS from its spec). It cannot be changed to another
power of two without a matching cache/import layout. Slot mapping remains a
signed 64-bit runtime value; negative slots are skipped. `spr` is K/(64*EPL):
4 at K=2048,EPL=8, 3 at K=768,EPL=4; `nw` is 16 for this 1024-thread launch.
A separate fixed-shape instantiation could constant-fold these divisors; the
shared generic wrapper must support other K and block sizes.

The static ~600 instructions include four alternative sites and the high-word
64-bit slow path. Decode slots <2^32 use the compiler's 32-bit bypass; counts
are not path cycles. MASTER PP8 prices the extra long-divide work <0.05
us/layer, `<0.05*48=2.4 us/step`, versus 30. QK10 prices the initial GEMV
setup ~0.1–0.2 us/layer, `0.2*48=9.6 us/step <30`. MoE initial setup's
exclusive exposed cost is unknown; no evidence assigns it >=0.625. Combining
unmeasured setup sites cannot turn the prep slow path into a priced saving.
No C3 build. C1 folds its own shape arithmetic as part of its router pool,
with no separate C3 timing credit. Six existing class/resource rows delta 0;
IR/source unchanged for C3. GPU stamps would need a new above-bar exclusive
arithmetic interval to reopen this item.

## C4: barrier dependency audit; no independent batches established

The listing is static block layout, not one executed sequence: MoE up has
GU1 and two-pass fallbacks, wide and narrow helpers. Source dependencies:

| Join in gemv.py | Earlier writes | Later reads/reuse | Why retain |
|---|---|---|---|
| topk_lds end | lids/lwts | expert pointer/routing weight | Selected expert depends on top-k |
| stage end | xs from activation | every stream dot reads xs | Cross-wave LDS producer/consumer |
| rows_nb clear | pl=0 | flush reads/adds pl | A late zero would overwrite a deposit |
| rows_nb gather | wave partials in pl | epilogue reads all waves | Reduction depends on all deposits |
| rows_nb end | g or output | SiLU reads g / next pass reuses pl | Arena lifetime and output visibility |
| publication | stores from every producing wave | downstream task | Store drain and task protocol |

Immutable gate/up W loads do not read each other's output. However their
**bodies** share xs/pl/g: after the first pass, the second pass clears/reuses
pl, and the final SiLU reads both rounded g rows. GU1 already merges these
loads on the legal whole-row condition. Moving loads alone needs a distinct
prefetch/register-lifetime mechanism; deleting the listed barriers is unsafe.
C1's router has single-assignment partials and proves its own removed clear
join; that proof is not applicable to MoE's `pl += v`.

Priced removable MoE service: 14.859–23.461 us/step /48 = 0.310–0.489
us/layer [E], below 0.625; barriers alone <=4*0.106=0.424. This service
calculation is **not a physical ceiling** on unknown skew/latency (MOE §3.2).
No newly proved independent-batch mechanism, so closed on the priced basis.
No C4 build; existing ISA/resources and IR unchanged. Future stamps may
reopen it with an exclusive >=0.625 interval and a safe ownership proof.
