# ETX progress report, 2026-10-11

**ETX's megakernel beats both the unfused kernels and the fastest vLLM setup we tested, on one model and one GPU.**
**Proof: 0.278 ms faster per token than vLLM's best tested setup, in all 5 paired rounds** (`results_vlbest2_2026-10-10/report.log:11`).

Conditions for every timing below: Qwen3-30B-A3B, bf16, batch 1, context 1024, one AMD MI300X virtual GPU, ROCm 7.14.0, host wall time per decoded token (`results_vlbest2_2026-10-10/report.log:3`).
Terms: *megakernel* is one GPU program that runs a whole decode step. *Fusion* means merging kernels into that one program.
*HIP graph* is AMD's standard way to replay separate kernels with low launch cost. `results_*/` paths are in `~/code/etx/`; repository files are at `13c7af0`.

Machinery that now exists [measured, read from code]:
- Kernel importer: lifts vLLM's own GPU kernels into the megakernel (`etx/importer/vllm_kernels.py:1`); 21 operators (`docs/OPERATOR-SPEC.md:3`).

- CI: that gate runs on every pull request and push to main (`.github/workflows/cpu-acceptance.yml:1-20`).
- Session harness: runs jobs on every GPU with deadlines and full logs (`etx/tools/gpu_jobs.py:1`).
