Fusion pays, and ETX does not yet beat vLLM. One persistent kernel beats a HIP-graph replay of the same tiles by 1.2%. The day began with fusion losing by 4.2%; the sign changed, and the system improved 16.2% against itself. The remaining 1.5% to vLLM is not in the orchestration.

Wall clock, the basis vLLM's benchmark uses. Three interleaved runs per row, one binary generation, all 32/32 tokens against HuggingFace greedy with every DSL operator of the last layer within 2 bf16 ulps of a CPU reference. Machine: 1× MI300X VF, ROCm 7.14. Confirmed on bare metal (ROCm 7.2.4) before the last change: 5.042 / 5.266 / 4.887, fusion margin +0.224 against −0.235 on 2026-09-30.

Why fusion now pays

Five changes account for the 16.2%. The first is the whole story; the rest are the tail.

ChangemsMechanism
Data-class coherence−0.317Every task's acquire was buffer_inv sc1 — a whole-L2 invalidate — so each phase began cold. DSL tiles now read activations coherently and skip the acquire; weights stay cached.
Unfolding the MoE top-k−0.231Our own earlier "optimisation": 448 expert tasks per layer each redid a 128-logit softmax on wave 0 while 15 waves waited. Ablation priced it at 0.676.
Async per-step host work−0.15220 synchronous HIP calls per step, a dead 241 KB memset, a 50 µs poll sleep.
Non-temporal weight loads−0.1066.08 GB read once per token were evicting the MALL-resident KV cache. L2 hit 31.9 → 34.6%.
Vectorising the coherent norm path−0.105A coherent access bypasses L1 and L2, so a 2-byte accessor issues one memory request per lane per element: the folded norm staged 4096 requests per task against o_proj's 1024 at four times the width. 16-byte accesses cut qkv's body 11.81 → 9.50 µs. Predicted not to move the MoE phases, which already use the wide path; it did not.
Phase width, import prune−0.082304 → 256 tasks; an unused imported tile was setting the LDS arena.

The invalidate is the one mechanism worth stating twice, because everything rests on it. An L2-resident phase costs 0.76 µs without it and 3.14 µs with it — 4.1×. A dependent load chain crossing it pays 1107 ns per hop against 103 ns — 10.6×. Both figures reproduce on both machines.

ETX's orchestration is spent; the tiles are not. Hand-off sits at its measured floor, start delay is below hardware jitter, host work is 0.135 ms, and the instruction cache — named in the literature as a megakernel's weakness — hits 99.90%. The gap to vLLM is 0.075 ms; the tile item alone is 1.29. Kernel quality was never ETX's claim, and it is now the whole of the difference.

One hardware limit bounds the tiles: occupancy is 4.000 of 8 waves per SIMD, capped by 128 VGPRs, with 85.9% of wave-cycles waiting and zero memory-unit stalls. Latency is unhidden; bandwidth is not the constraint. Reaching 6 waves needs VGPR ≤ 85 and LDS ≤ 21845 B together — a tile redesign, not a flag. Smaller workgroups do nothing: the register term is 4 at any size.

Batch: the premise was wrong

BatchvLLMETXRatio
14.8615.2671.08×
22.7933.5981.29×
41.8203.4661.90×

ETX replicates where vLLM batches. Task counts are exactly linear in request count — 59,978 / 119,956 / 239,912 — so every request streams its own copy of the weights, while vLLM reads a weight tile once per B-column activation matrix. Batch is ETX's worst regime, not its best.

The remedy was built and lost. A skinny GEMM serving two columns from one weight read cost +0.29 ms: the second column costs 90% of the first, because the tile sits where compute time equals stream time and extra columns double the LDS traffic while saving only the weight stream; and a batched phase must wait on every request's previous event, removing the slack replication provides. LDS caps the design at B=2 regardless. Proper batching needs matrix instructions for B>1 and whole-layer batching with no per-phase join — a separate project.

Three measurement errors, ours

  1. Traces taken during the prompt. Limited to the first eight steps — the teacher-forced prompt, sequence length 1–8. vLLM's attention kernel partitions by a hardcoded 256 tokens and exits past the end, so 16 of 20 tasks looked trivial and we concluded a 4.3× work imbalance. In decode the spread is 1.17×. Timing was unaffected; the attention block was understated by 0.21 ms.
  2. A statistic that charged imbalance to skew. In-phase skew was computed as span minus mean body, but a phase ends when its last task does. Recomputed: 0.414 start delay, 0.244 imbalance.
  3. The baseline measured at the wrong width. The streaming benchmark used 256-thread workgroups; the tiles use 1024. Corrected, the MoE residual falls 0.532 → 0.476 and the router's 0.164 → 0.046 — most of what we had charged to ETX there was the hardware floor.

The compiler and runtime half of this project is at its measured floor. What separates ETX from vLLM at batch 1 is hand-written tiles against kernels AMD has tuned — worth saying plainly, because it is not what ETX set out to prove, and because what it did set out to prove is now measured on two machines against the strong baseline.
