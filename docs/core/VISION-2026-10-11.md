Goal: turn ETX into one system that runs any standard decoder model from its Hugging Face
checkpoint, with no per-model code. A new model should run correctly on day 0 with one
command.

Scope

   ●​ In: standard decoders: GQA attention, RMSNorm, rotary embeddings, dense or top-k
      MoE

Components to build

   1.​ Model front end. Reads config.json and the weights, maps them to a standard list
        of blocks, and builds the task graph. Generalize examples/llm and retire the
       per-model directories (vllm_llm and dsv2lite stay only as benchmarks).
   2.​ Operator library. Each operator is defined once, parameterized by shape, with default
       task code that is correct for any shape.
   3.​ Task code registry. One interface contract per task: arguments, tile coordinates,
       register and LDS budget, coherence mode. Optimized code (vLLM imports, Fleet tiles,
       hand- or AI-written) registers with the shapes it supports, passes a per-task test against
       a reference, and is picked automatically. Anything else falls back to the default.
   4.​ Shape-generic host and runtime. Weight loading, argument blocks and KV cache are
       all derived from the model description. No hard-coded shapes, no ETX_VL_* switches.
       Batch size is a parameter: correct at any size now, fast later.
   5.​ Automatic tuning. Task sizes are chosen per model and GPU by timing candidates on
       the GPU, replacing the Qwen-tuned constants, and cached.
   6.​ One-command validation. Build, compare tokens against Hugging Face, repeat runs
       for identical output, benchmark against vLLM, and report.
   7.​ Chip backend boundary. Task code, synchronization primitives and cost tables per
       chip, behind one interface. MI300X only for now. It should support Nvidia as well.

Keep: the compiler core (IR, passes, code generator, runtime), the calibration benchmarks and
the correctness gates.

Done when

   ●​ Two unseen models run with minimal intervention and they should match or beat
      TileRT.

Expectations: day 0 means correct, not fastest. New models run on the generic task code until
optimized code is registered. Performance work continues separately and plugs in through the
registry.
